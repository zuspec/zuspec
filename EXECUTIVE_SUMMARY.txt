KEY FINDINGS
================================================================================

1. ATTRIBUTE ATTACHMENT STRATEGY
   The pipeline uses _zdc_struct to bridge PSS→IR and Python runtime:
   - IrToRuntimeBuilder attaches _zdc_struct to struct classes
   - randomize() uses _extract_struct_type() to find it
   - Fallback: DataModelFactory lazy-builds IR on demand
   - ACTION: Ensure _zdc_struct always present before randomization

2. BUILD ORDER MATTERS
   IrToRuntimeBuilder.build() must follow:
     1. Enums (dependencies for field types)
     2. Structs (dependencies for component/action fields)
     3. Components (dependencies for action parent types)
     4. Actions (need parent components already built)
   
   Current implementation is CORRECT ✅

3. INSPECT PROBLEM IS REAL BUT FIXABLE
   Dynamic classes fail inspect.getsource() → OSError
   
   Option A (RECOMMENDED):
     • Populate DataModelFactory cache when building IR
     • register(cls, struct_ir) → DataModelFactory knows about built classes
     • randomize() finds IR in cache, skips source lookup
   
   Option B (WORKAROUND):
     • Detect _zdc_struct presence in DataModelFactory._extract_method_body()
     • Skip inspect, use pre-built statements
   
   Option C (HACKY):
     • Monkey-patch inspect.getsource() to handle dynamic classes
     • Not recommended

4. CONSTRAINT METADATA IS COMPLETE
   Field class has all needed metadata:
     - rand_kind: "rand", "randc", or None
     - domain: (min, max) tuple or list of values
     - size: array sizes
     - These ARE populated during AST→IR translation
     - Solver DOES use them correctly
   ✅ All 6 constraint tests pass

5. REGISTRY IS WELL-DESIGNED
   ClassRegistry supports both styles:
     • Dict-style: registry['MyC::MyA'], registry['Packet']
     • Attribute-style: registry.Top, registry.MyC.MyA
     • Qualified names for actions, simple names for components/structs
     • Standard library types included by default
